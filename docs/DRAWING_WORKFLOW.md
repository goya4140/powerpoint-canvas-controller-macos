# 论文插图制作流程

## 为什么先做 1 → 1

从 Method 文本直接生成一张逻辑正确、版式成熟、审美稳定的论文插图，同时涉及语义理解、信息选择、拓扑设计、排版、视觉风格和绘图执行。任何一层出错，最终结果都可能不可用。

仓库因此采用三个递进阶段：

| 阶段 | 输入 | 要验证的能力 |
|---|---|---|
| **1 → 1 临摹** | 参考图 | 是否能重建结构、版式、视觉语法和可编辑对象 |
| **0.5 → 1 受控改写** | 参考图 + Method 文本 | 是否能保持表达逻辑，同时改变风格或排版 |
| **0 → 1 原创生成** | Method 文本 + 要求 | 是否能自主完成内容选择、构图和视觉表达 |

当前只把第一阶段作为主要交付目标。

## 1 → 1 工作流

### 0. 建立来源记录

记录：

- 论文标题；
- 发表会议与年份；
- Figure 编号；
- 论文页面；
- 本地参考图；
- 参考图裁剪范围；
- 一句话复现逻辑。

参考图只作为研究与评估输入，不作为可复用素材。

### 1. 识别画布与全局轮廓

先判断：

- 横向、纵向或近方形比例；
- 主阅读方向；
- 面板数量和相对宽度；
- 最大模块的位置；
- 留白和密度分布；
- 是否存在闭环、分支、对照或层级。

这一阶段只画大框。全局轮廓不相似时，不进入细节。

### 2. 拆解主模块和连接图

为每个主模块分配稳定名称，并记录：

- 形状；
- 位置和尺寸；
- 填充、描边、圆角和旋转；
- 文本；
- 与其他模块的连接方向；
- 是否是背景区域。

技术箭头不能因为“画面上应该有一条线”而猜测。参考图信息不足时，保留可见关系并声明语义不确定。

### 3. 识别重复视觉语法

把重复元素编码为可生成的 motif：

- token 行或网格；
- Transformer block；
- 图像或卡片堆栈；
- 网络节点与边；
- 多尺度层；
- 重复输入/输出示例；
- skip connection 或 feedback path。

重复 motif 要由多个原生对象生成，而不是贴入一张截图。

### 4. 编码 Scene Spec

按照 [`references/reference-recreation.md`](../references/reference-recreation.md) 使用：

- `shape`
- `text`
- `line`
- `connector`
- `stack`
- `tokens`
- `network`

坐标使用统一的 1200 × 600 画布。重要对象使用稳定名称。

### 5. 校验与生成

```bash
npm run validate:reference
npm run build:reference
```

生成器同时输出：

- 10 页或单页可编辑 PPTX；
- 每页 PNG；
- 每页 layout JSON；
- 参考图/复现图左右拼接图；
- 来源索引。

### 6. 视觉比较

按以下顺序比较：

1. 主阅读方向是否一致；
2. 面板数量和比例是否一致；
3. 主模块的相对位置与尺寸是否一致；
4. 箭头、反馈、分支和重复关系是否一致；
5. 色板、线宽、圆角和字体层级是否一致；
6. 区分性细节是否保留。

不要因为小细节相似而忽略大结构错误。

### 7. QA

运行：

```bash
npm run check:reference
```

并逐页检查：

- 无越界、裁切和意外换行；
- 连接线不被背景面板遮挡；
- 箭头方向正确；
- 标签位于连接线上层；
- 背景区域位于连接线下层；
- 关键对象均为独立原生对象；
- 参考来源与 Figure 编号可追溯。

### 8. 返工

- **全局轮廓错误**：回到步骤 1；
- **技术关系错误**：回到步骤 2；
- **密度和细节错误**：回到步骤 3；
- **颜色和字体错误**：修改视觉 token；
- **输出不可编辑**：替换位图为原生 motif；
- **对比图不清楚**：修正 `reference_crop`，不改动原始参考图。

所有修正应写回 Scene Spec，再重新生成。

## 0.5 → 1 的进入条件

只有满足以下条件后才进入 0.5 → 1：

- 1 → 1 基准覆盖多种常见论文图拓扑；
- 主结构和箭头关系能稳定复现；
- 对比输出和人工评分可重复；
- Scene Spec 能支持局部替换和重排；
- Method 语义图可以映射到参考图对象。

0.5 → 1 会新增“语义对齐层”：判断参考图中每个视觉对象是否由新 Method 支持，并在保留视觉语法的同时替换技术内容。

## 0 → 1 的进入条件

0 → 1 需要在 0.5 → 1 之上再解决：

- 从 Method 中选择应该画什么；
- 为技术关系选择合适的图拓扑；
- 从参考库中检索或组合视觉语法；
- 生成多个构图候选；
- 在没有参考图的情况下判断美学和逻辑质量。

原有 Level 1 语义图工作流仍是这一阶段的技术内容基础，但不再被视为完整的论文插图生成方案。

## 交付标准

当前 1 → 1 阶段至少交付：

- 可编辑 PPTX；
- 单图渲染 PNG；
- 参考图/复现图拼接对比；
- 场景规格；
- 来源链接；
- 已知简化与版权边界。
